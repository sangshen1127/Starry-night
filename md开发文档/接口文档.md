# 个人博客 · 接口文档

> 版本：v0.2
> 更新日期：2026-10-21
> 对应数据库：`my_blog`（MySQL 8.0，utf8mb4）
> 对应后端：Spring Boot 4.1.1 + MyBatis-Plus + Spring Security（Session）
> 对应前端：Vue 3 + Vite + axios

---

## 1. 通用约定

### 1.1 Base URL

| 环境 | 地址 |
|---|---|
| 本地开发 | `http://localhost:8080` |
| 前端开发 | 浏览器请求 `/api/**`，由 Vite 代理到 `http://localhost:8080` |
| 生产 | 同域部署，Nginx 把 `/api/**` 反代到后端 |

所有接口路径都以 `/api` 开头。前端 axios 的 `baseURL` 设为 `/api`，业务代码里只写 `/posts`、`/admin/posts`。

### 1.2 统一响应格式

**所有**接口（包括出错时）都返回这个结构：

```json
{
  "code": 1,
  "message": "success",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | **`1` 表示成功，`0` 表示失败** |
| `message` | string | 成功时为 `success`，失败时为给用户看的中文提示 |
| `data` | any | 成功时的业务数据；失败时为 `null` |

分页接口的 `data` 固定为：

```json
{
  "list": [],
  "total": 0,
  "page": 1,
  "size": 10
}
```

### 1.3 状态码与错误码

| HTTP 状态 | code | 含义 | 典型场景 |
|---|---|---|---|
| 200 | 1 | 成功 | — |
| 400 | 0 | 参数校验失败 | 标题为空、评论超长、页码非法 |
| 401 | 0 | 未登录 / 登录已过期 | 未带 Session 访问后台接口 |
| 403 | 0 | 已登录但无权限 | 普通用户访问管理员接口 |
| 404 | 0 | 资源不存在 | 文章 id 不存在、文章未发布 |
| 409 | 0 | 冲突 | 友链 URL 已存在 |
| 429 | 0 | 请求过于频繁 | 评论提交过快、登录失败次数过多 |
| 500 | 0 | 服务器内部错误 | 未捕获的异常 |

约定：

- `code` 只表示成功 / 失败：**`1` 成功，`0` 失败**
- 具体失败原因看 **HTTP 状态码** 和 `message`
- HTTP 状态码保持语义正确（400/401/404…），**不要一律返回 200**，否则前端没法区分“没登录”和“参数错”

### 1.4 认证方式

- 采用 **Session + Cookie**。登录成功后服务端通过 `Set-Cookie` 下发 `JSESSIONID`
- Cookie 属性：`HttpOnly`、`SameSite=Lax`，生产环境加 `Secure`
- 前端**不需要手动带 token**，同域下浏览器会自动携带；如果前后端分开部署，axios 需要设置 `withCredentials: true`
- 需要登录的接口统一在 `/api/admin/**` 和 `/api/auth/me`、`/api/auth/logout` 下

前端统一处理：

| 收到 | 处理方式 |
|---|---|
| `401` | 清除本地登录态，跳转登录页 |
| `403` | 提示“没有权限” |
| `429` | 提示“操作太频繁，请稍后再试” |
| `code` 为 `0` | 直接弹出 `message` |

### 1.5 分页约定

| 参数 | 类型 | 默认 | 约束 |
|---|---|---|---|
| `page` | int | 1 | 从 **1** 开始，小于 1 返回 400 |
| `size` | int | 10 | 1～50，超出返回 400 |

排序：文章列表按 `published_at DESC`，评论按 `created_at DESC`，友链按 `sort_order ASC`。

### 1.6 字段命名与时间

- 数据库用下划线（`cover_url`），接口一律用 **小驼峰**（`coverUrl`）
- 时间统一格式：`yyyy-MM-dd HH:mm:ss`（如 `2026-10-21 17:30:00`）
- 时间统一按 `Asia/Shanghai` 处理
- 所有 id 均为 `number`（BIGINT 在 JS 安全整数范围内，暂不转字符串）

### 1.7 请求格式

- 除文件上传外，请求体一律 `Content-Type: application/json`
- 文件上传用 `multipart/form-data`
- 字符串字段需要做长度和空值校验，服务端不能只依赖前端

## 3. 前台接口

### 3.1 文章列表

```
GET /api/posts?page=1&size=10&keyword=spring
```

鉴权：否

| 参数 | 位置 | 必填 | 类型 | 说明 |
|---|---|---|---|---|
| `page` | query | 否 | int | 页码，默认 1 |
| `size` | query | 否 | int | 每页条数，默认 10，最大 50 |
| `keyword` | query | 否 | string | 标题模糊搜索，最长 50 字符 |

只返回 `status = 'published'` 的文章，按 `published_at` 倒序。

**响应**

```json
{
  "code": 1,
  "message": "success",
  "data": {
    "list": [
      {
        "id": 3,
        "title": "我的第一篇博客",
        "summary": "这是摘要，列表页展示用",
        "coverUrl": "/uploads/2026/10/cover.webp",
        "publishedAt": "2026-10-20 10:00:00",
        "viewCount": 12
      }
    ],
    "total": 1,
    "page": 1,
    "size": 10
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | number | 文章 id |
| `title` | string | 标题 |
| `summary` | string \| null | 摘要，未填时为 null，前端可截取正文前 100 字 |
| `coverUrl` | string \| null | 封面图地址 |
| `publishedAt` | string \| null | 发布时间 |
| `viewCount` | number | 浏览次数 |

> 列表**不返回** `content`，避免一页传几百 KB。

### 3.2 文章详情

```
GET /api/posts/3
```

鉴权：否

| 参数 | 位置 | 必填 | 类型 | 说明 |
|---|---|---|---|---|
| `id` | path | 是 | number | 文章 id |

**响应**

```json
{
  "code": 1,
  "message": "success",
  "data": {
    "id": 3,
    "title": "我的第一篇博客",
    "summary": "这是摘要",
    "coverUrl": "/uploads/2026/10/cover.webp",
    "content": "# 标题\n\n正文的 Markdown 原文",
    "publishedAt": "2026-10-20 10:00:00",
    "updatedAt": "2026-10-21 09:00:00",
    "viewCount": 13,
    "commentCount": 2
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `content` | string | Markdown 原文，**前端负责渲染和 XSS 过滤** |
| `commentCount` | number | 已通过审核的评论数 |

**错误**

| 情况 | 返回 |
|---|---|
| id 不存在 | 404 |
| 文章是草稿 | 404（对游客不可见，不要返回 403，避免暴露草稿存在） |

> 每次成功读取详情，`view_count + 1`。是否防刷（同 IP 10 分钟内只计一次）由你决定，第一版可以直接加。

### 3.4 提交评论

```
POST /api/comments
Content-Type: application/json
```

鉴权：否（游客可提交）

**请求体**

```json
{
  "postId": 3,
  "nickname": "小明",
  "email": "ming@example.com",
  "website": "https://example.com",
  "content": "写得好"
}
```

| 字段 | 必填 | 类型 | 约束 |
|---|---|---|---|
| `postId` | 是 | number | 必须是已发布文章 |
| `nickname` | 是 | string | 1～32 字符，去首尾空格 |
| `email` | 否 | string | 合法邮箱，最长 128 |
| `website` | 否 | string | 必须以 `http://` 或 `https://` 开头，最长 255 |
| `content` | 是 | string | 1～500 字符，**纯文本，不接受 HTML** |

**响应**

```json
{
  "code": 1,
  "message": "评论提交成功，审核通过后显示",
  "data": null
}
```

入库时 `status = 'pending'`，同时记录 `ip` 和 `user_agent`。

**错误**

| 情况 | 返回 |
|---|---|
| 内容为空或超长 | 400 |
| postId 不存在或未发布 | 404 |
| 60 秒内重复提交 | 429 |
| 同一 IP 1 小时超过 10 条 | 429 |

**安全要求**

- 内容按纯文本存储，渲染时转义，**禁止直接 innerHTML**
- 服务端记录 IP 和 User-Agent，便于排查和拉黑
- 建议加一个隐藏的蜜罐字段，被填写则直接丢弃

```

```

{
  "code": 1,
  "message": "success",
  "data": {
    "latestPosts": [
      {
        "id": 3,
        "title": "我的第一篇博客",

        "coverUrl": "/uploads/2026/10/cover.webp",
        "publishedAt": "2026-10-20 10:00:00"
      }
    ],
    "latestComments": [
      {
        "id": 8,
        "postId": 3,

        "createdAt": "2026-10-21 12:00:00"

    ],

- `friendLinks`：同 3.5

> 这是**可选接口**。如果不想写，前端分别调 3.1、3.3、3.5 也可以，只是首页会发三个请求。

## 4. 认证接口

### 4.1 登录

```
POST /api/auth/login
Content-Type: application/json
```

**请求体**

```json
{
  "username": "admin",
  "password": "你的密码"
}
```

**成功响应**

```json
{
  "code": 1,
  "message": "登录成功",
  "data": {
    "id": 1,
    "username": "admin",
    "nickname": "站长"
  }
}
```

同时响应头带 `Set-Cookie: JSESSIONID=...; HttpOnly; SameSite=Lax; Path=/`。

**错误**

| 情况 | 返回 |
|---|---|
| 用户名或密码错误 | 401，`message` 统一为“用户名或密码错误”，不要区分是哪个错 |
| 5 分钟内失败 5 次 | 429（**v1 暂未实现**，见第 9 节待定事项） |
| 账号被禁用 | 403（**v1 暂未实现**，`users` 表当前没有 `enabled` 字段） |

> **实现提示**：Spring Security 默认的 `/login` 只接受
> `application/x-www-form-urlencoded`，和你这里约定的 JSON 不一致。
> 两个选择：① 前端改成 `URLSearchParams` 发；② 自己写 Controller，
> 注入 `AuthenticationManager` 手动认证，成功后把 `SecurityContext` 存入 Session。
> 推荐 ②，契约更可控，也更容易理解认证流程。

### 5.3 新建文章

```
POST /api/admin/posts
Content-Type: application/json
```

**请求体**

```json
{
  "title": "我的第一篇博客",
  "summary": "这是摘要",
  "coverUrl": "/uploads/2026/10/cover.webp",
  "content": "# 标题\n\n正文",
  "status": "draft"
}
```

| 字段 | 必填 | 类型 | 约束 |
|---|---|---|---|
| `title` | 是 | string | 1～120 字符，去首尾空格 |
| `summary` | 否 | string | ≤300 字符，为空时可由后端截取正文前 100 字 |
| `coverUrl` | 否 | string | ≤255，必须是本站 `/uploads/` 或 https 地址 |
| `content` | 是 | string | 非空，Markdown 原文 |
| `status` | 否 | string | `draft` / `published`，默认 `draft` |

**响应**

```json
{ "code": 1, "message": "创建成功", "data": { "id": 4 } }
```

**规则**

- `status = 'published'` 时，自动把 `published_at` 设为当前时间
- `status = 'draft'` 时，`published_at` 保持 NULL

---

### 5.4 更新文章

```
PUT /api/admin/posts/3
```

请求体同 5.3（整体覆盖）。`status` 不传则保持不变。

**响应**

```json
{ "code": 1, "message": "保存成功", "data": null }
```

**规则**

- 草稿改为 `published` 且 `published_at` 为 NULL 时，补上当前时间
- 已发布改为 `draft` 时，`published_at` 保留（重新发布时不再改，或按你的意愿清空，二选一，写进注释）

### 5.14 上传图片

```
POST /api/admin/upload
Content-Type: multipart/form-data
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `file` | file | 图片文件，必填 |

**限制**

- 单文件 ≤ 5MB（`application.yml` 已配）
- 允许类型：`image/jpeg`、`image/png`、`image/webp`、`image/gif`
- 校验以**文件内容**为准，不能只看扩展名或 `Content-Type`
- 存储路径：`./uploads/yyyy/MM/{uuid}.{ext}`，文件名由服务端生成，**不使用原始文件名**
- 禁止 SVG（可内嵌脚本）

**响应**

```json
{
  "code": 1,
  "message": "上传成功",
  "data": {
    "url": "/uploads/2026/10/6f1c2a9e.webp",
    "name": "photo.webp",
    "size": 204800
  }
}
```

**错误**

| 情况 | 返回 |
|---|---|
| 文件为空 | 400 |
| 类型不支持 | 400 |
| 超过 5MB | 400 |
| 未登录 | 401 |

**访问方式**

上传后的文件通过 `/uploads/**` 访问，需要配置静态资源映射（代码里加，不在 yml 里配）。

## 7. 建议的实现顺序

按这个顺序写，每一步都能单独验证，不会堆到最后一起爆炸：

1. **`GET /api/posts`** —— 打通 Controller → Service → Mapper → MySQL 整条链路
2. **`GET /api/posts/{id}`** —— 验证路径参数、404 处理
3. **登录三件套** —— `POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout`，此时再配 Security 的放行规则
4. **后台文章 CRUD** —— 先能写，才能有内容
5. **上传** —— 文章里要插图
6. **评论提交 + 审核** —— 唯一对外的写入口，重点做校验和限流
7. **友链** —— 最简单，用来练手
8. **`GET /api/home` + `GET /api/admin/stats`** —— 收尾
