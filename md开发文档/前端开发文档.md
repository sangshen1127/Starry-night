## 1. 项目概览

### 1.1 本期做了什么

Start Night 是一个偏二次元气质的个人博客。本次把后端已经完成的九个公开接口全部接进了前端：

| 接口 | 前端落点 |
|---|---|
| `GET /api/home` | 首页聚合（文章 / 留言 / 友链） |
| `GET /api/posts` | `/posts` 文章归档：标题搜索 + 分页 |
| `GET /api/posts/{id}` | `/posts/:id` 文章详情，Markdown 渲染 |
| `GET /api/posts/{id}/comments` | 详情页“留言”列表，只显示已通过 |
| `POST /api/comments` | 详情页留言表单，提交后进入审核 |
| `GET /api/friend-links` | `/friends` 友链页 |
| `POST /api/auth/login` | `/login` 站长登录 |
| `GET /api/auth/me` | 刷新页面后恢复登录态 |
| `POST /api/auth/logout` | Header 账号菜单退出登录 |

### 1.2 页面清单

| 路由 | 页面 | 是否需登录 | 说明 |
|---|---|---|---|
| `/` | 首页 | 否 | 夜空 Hero + 最新文章 + 侧栏 |
| `/posts` | 文章归档 | 否 | 搜索、分页、空/错状态 |
| `/posts/:id` | 文章详情 | 否 | Markdown 正文 + 评论 |
| `/friends` | 友链 | 否 | 友链卡片网格 |
| `/login` | 站长登录 | 否 | 登录 / 已登录态 |
| 其他 | 404 | 否 | 页面不存在 |

### 1.3 本期不包含

- **后台内容管理页面**：九个接口里只有认证，没有文章 / 评论 / 友链的后台 CRUD 接口。登录目前用于保持站长会话，后台管理是下一阶段。
- 分类、标签、阅读时长：接口没有这些字段，前端没有伪造。
- 全文搜索：`/api/posts?keyword=` 只按标题模糊查询。
- 评论编辑 / 删除、点赞、RSS、站点设置后台。
- 更换主题、字体缩放面板。

## 2. 技术选型

| 技术 | 版本 | 用途 |
|---|---|---|
| Vue | 3.5.x | `<script setup>` + Composition API |
| TypeScript | 5.9.x | strict 模式，接口字段可空性检查 |
| Vite | 7.3.x | 开发代理、按路由拆包 |
| Vue Router | 4.6.x | 首页 / 归档 / 详情 / 友链 / 登录 / 404 |
| Pinia | 4.1.x | 只存登录态（user / loading / restored / error） |
| Axios | 1.20.x | 统一 `{ code, message, data }` 与错误 |
| markdown-it | 15.x | 后端 Markdown 正文渲染 |
| DOMPurify | 3.x | Markdown 渲染后的 XSS 白名单过滤 |

### 2.1 设计取舍

- **没有 UI 组件库**：公开站点需要定制视觉；表单、分页、弹层都是自写 CSS，避免引入整包组件库。
- **Pinia 只存 auth**：文章 / 评论 / 友链都是页面局部数据，页面卸载就释放；没有把列表塞进全局 store。
- **Markdown 按需加载**：`markdown-it` + `DOMPurify` 只在详情页 chunk 中加载，不拖慢首页。
- **不加语法高亮库**：当前代码块用统一深色样式；以后需要再做 Shiki / highlight.js。
- **不引入 SSR**：本期是纯 SPA；SEO 以静态 meta + 路由 title 为主，后续可预渲染。

## 3. 页面风格：夜行手帐

### 3.1 关键词

> **夜空、月光、纸面、留白、轻二次元**

风格不是“满屏贴纸”，而是：

1. 首页一个夜空 Hero，右侧固定给动漫人物插画；
2. 其余页面回到米白纸面，用大标题、细线、等宽小标签建立“手帐感”；
3. 紫色只做交互强调，金色只做星光点缀；
4. 角色图是页面里最热闹的元素，其他区域保持安静。

### 3.2 色彩 token

定义在 `src/styles/tokens.css`：

| Token | 值 | 用途 |
|---|---|---|
| `--paper` | `#f7f4ee` | 页面纸面底色 |
| `--surface` | `#fffdf8` | 卡片 / 表单 / Header |
| `--ink` | `#1b2233` | 标题与主要文字 |
| `--ink-2` | `#3d465a` | 正文、导航 |
| `--muted` | `#626b7f` | 日期、摘要、说明 |
| `--violet` | `#6454c8` | 链接、按钮、选中态 |
| `--gold` | `#c6963d` | 星光、眉题 |
| `--night-0/1/2` | `#080c1a / #0d1225 / #181e38` | Hero、页脚、登录卡片 |
| `--moon` | `#f5ead2` | 月亮、亮按钮 |
| `--star` | `#f4d58d` | 星星、强调文字 |

建议比例：**70% 纸面、20% 墨色 / 夜空、10% 紫金强调**。

### 3.3 字体与层级

- 中文：系统无衬线栈（PingFang / HarmonyOS Sans / Microsoft YaHei）。
- 英文、日期、小标签：等宽字体栈。
- 不加载外部字体，避免首屏闪烁。
- 标题用重字重 + 负字距；正文行高 1.8～1.95。

| 层级 | 大小 | 场景 |
|---|---|---|
| 首页 H1 | 2.7～4.4rem | 两行，第二行星光金 |
| 页面 H1 | 2.2～3.2rem | 归档 / 详情 / 友链 |
| 区块标题 | 1.6～1.9rem | 最新文章 / 留言 |
| 卡片标题 | 1.02～1.18rem | 文章卡片 |
| 正文 | 0.86～0.98rem | 摘要 / Markdown |
| 微型标签 | 0.52～0.64rem | 等宽、字距 |

### 3.4 各页面布局

#### 首页

```text
Header（品牌 / 导航 / 登录）
┌──────────────────────────────────────┐
│ 夜空 Hero：两行标题 + CTA + 4:5 角色位 │
└──────────────────────────────────────┘
┌──────────────────────────┬───────────┐
│ 最新文章：主推 + 卡片网格  │ 关于      │
│                          │ 最新留言   │
│                          │ 友链      │
└──────────────────────────┴───────────┘
夜空页脚
```

- 内容最大宽 1200px，主栏 + 330px 侧栏。
- 只有 1 篇剩余文章时，自动使用横向宽卡，不留半页空白。
- 区块标题右侧有“全部文章”入口；友链卡底部有“全部友链”。

#### 文章归档 `/posts`

```text
┌──────────────────────────────────────┐
│ ARCHIVE · 文章                        │
│ 全部文章                    [搜索胶囊] │
│ 共 N 篇 / 关键词                       │
├──────────────────┬───────────────────┤
│ 文章卡片          │ 文章卡片           │
├──────────────────┼───────────────────┤
│ 文章卡片          │ 文章卡片           │
└──────────────────┴───────────────────┘
             [分页]
```

- 纸面直接进入，不再放第二块夜空 Hero，避免每页都“开大灯”。
- 搜索是标题关键词，输入框右侧按钮提交；URL 同步 `?keyword=&page=`。
- 卡片底部固定“阅读全文”，整张卡可点。

#### 文章详情 `/posts/:id`

```text
← 返回文章列表
NIGHT NOTE · 夜色笔记
标题
摘要
日期 · 阅读 · 留言
[有封面才显示 16:9 大图]
Markdown 正文（最大 860px 阅读列）
────────────
留言（已通过 N 条）
留言列表
写下想说的话（昵称 / 邮箱 / 网站 / 留言）
```

- 详情页使用单列阅读布局，正文宽度克制。
- 没有封面就干净地进入文字，不强行塞渐变占位大图。
- Markdown 标题、引用、代码、表格、图片都有对应排版。
- 评论区在正文下方，留言表单始终保持在同一阅读列。

#### 友链 `/friends`

- 最大宽 1100px，3 列 → 2 列 → 1 列。
- 每张卡片：圆形头像 / 首字占位、名称、描述、右上角外链箭头。
- 下方有“想交换友链？在留言板留下地址”的引导。

#### 登录 `/login`

- 米白页面上放一张夜空卡片，复用 StarField。
- 卡片 480px 宽，深色底、米色按钮；登录后同一张卡片切换为“欢迎回来”。
- 站长入口保持克制，不抢首页视觉。

#### Header 登录态

- 未登录：右侧显示用户图标 + “登录”；移动端只显示图标。
- 已登录：圆形首字 + 昵称，点击打开账号浮层，显示 `@username` 与退出按钮。
- 移动端账号按钮和汉堡按钮并排，不再垂直堆叠。

| ≤ 640px | Header 账号文字隐藏；详情表单单列 |

已实测路由：`/`、`/posts`、`/posts/1`、`/friends`、`/login`、`/posts/999`  
已测宽度：**320 / 360 / 390 / 768 / 1024 / 1440**，无横向滚动。

### 3.6 动效

- 首页 Hero 文案 / 插画入场 0.8～0.95s。
- 星星缓慢闪烁，首屏偶发流星；不铺满整页。
- 卡片 hover 上浮 3～4px；详情封面不缩放。
- 骨架屏微光、认证浮层淡入。
- 全部遵守 `prefers-reduced-motion: reduce`。

### 3.7 角色插画与图片规范

首屏角色位组件：`src/components/CharacterArt.vue`。当前是月亮 + 星座 + “角色插画位”占位图。

#### 替换步骤

1. 图片放到：
   ```
   frontend/public/images/character/hero.webp
   ```
2. 修改 `src/config/site.ts`：
   ```ts
   characterImage: '/images/character/hero.webp',
   characterAlt: '你的人物插画描述',
   ```
3. 刷新。路径为空或加载失败时自动回退占位图，不出现破图。

侧栏头像：`avatarImage` 同配置方式。

#### 规格建议

| 用途 | 比例 | 建议 | 说明 |
|---|---|---|---|
| Hero 角色 | **3:4 / 4:5 竖图** | 1200×1600 以内 | 透明或深色夜空背景 |
| 侧栏头像 | 1:1 | 256 或 512 | 圆形裁切 |
| 文章封面 | 16:10 | 1200×750 | `coverUrl` 返回 |
| 友链头像 | 1:1 | 128 | `avatarUrl` 返回 |

- 优先 WebP / AVIF；Hero < 400KB，封面 < 200KB。
- 人物脸放画面上方约 1/3，底部留出身体空间；不要贴边。
- 一页只放一个角色主视觉，其他卡片不要再堆人物。
- 插画本身的颜色可以丰富，但页面其他区域继续低饱和紫金。
- **不要**：贴纸、胶带、速度线、满屏小图标、自动音乐、重型鼠标跟随粒子。

### 3.8 Markdown 排版

- 正文：0.98rem / 1.95 行高；移动端 0.94rem。
- H2 带底部分隔线；H3/H4 保持层级。
- 引用：纸面底 + 紫色左边框。
- 行内代码：紫色浅底；代码块：夜空深色、横向滚动。
- 图片最大宽度 100%，自动高度；表格横向滚动。
- 站外链接新窗口打开，带 `rel="noopener noreferrer"`。

## 5. 接口契约（九个全部接入）

### 5.1 通用约定

- Base URL：`/api`，开发环境由 Vite 代理到 `http://localhost:8080`。
- 成功：
  ```json
  { "code": 1, "message": "success", "data": {} }
  ```
- 失败：`code: 0`，HTTP 状态码有语义。
- 时间格式：`yyyy-MM-dd HH:mm:ss`（Asia/Shanghai）。
- 字段小驼峰，id 为 number。
- 统一请求封装：`src/api/http.ts` → `get()` / `post()`。
  - `get<T>()` 返回 `data`。
  - `post<T>()` 返回 `{ data, message }`，因为评论成功提示在 `message` 中。
  - 所有错误转成 `ApiError(message, status, code)`。

### 5.2 首页：`GET /api/home`

公开，无参数，一次返回三块内容：

```json
{
  "code": 1,
  "message": "success",
  "data": {
    "latestPosts": [
      {
        "id": 2,
        "title": "关于数据库设计",
        "summary": null,
        "coverUrl": null,
        "publishedAt": "2026-10-21 19:31:00",
        "viewCount": 0
      }
    ],
    "lastestComments": [
      {
        "id": 2,
        "postId": 1,
        "postTitle": "我的第一篇博客",
        "nickname": "小红",
        "content": "学到了",
        "createdAt": "2026-10-24 21:42:56"
      }
    ],
    "friendLinks": [
      {
        "id": 1,
        "name": "阮一峰的网络日志",
        "url": "https://www.ruanyifeng.com/blog/",
        "avatarUrl": null,
        "description": "每周分享科技动态"
      }
    ]
  }
}
```

- `latestPosts`：最新 5 篇已发布文章，`[0]` 做主推，其余做网格 / 单篇宽卡。
- `lastestComments`：最新 5 条已通过评论，带 `postId` / `postTitle`。
- `friendLinks`：同 5.7。
- 首页不返回总数、分类、标签、阅读时长、featured 标记；前端不伪造。
- 实际返回 key 是 `lastestComments`，接口文档写 `latestComments`；前端两种都兼容，见 5.9。

### 5.3 文章归档：`GET /api/posts`

公开。只返回 `status = 'published'`，按 `publishedAt DESC, id DESC`。

| 参数 | 位置 | 默认 | 约束 |
|---|---|---|---|
| `page` | query | 1 | ≥ 1 |
| `size` | query | 10 | 1～50 |
| `keyword` | query | 无 | 只按**标题**模糊查询 |

响应是 `PageResult<PostListItem>`：

```json
{
  "code": 1,
  "message": "success",
  "data": {
    "list": [
      {
        "id": 1,
        "title": "我的第一篇博客",
        "summary": "这是摘要",
        "coverUrl": null,
        "publishedAt": "2026-10-20 10:00:00",
        "viewCount": 12
      }
    ],
    "total": 2,
    "page": 1,
    "size": 8
  }
}
```

- 列表**不返回** `content`。
- 前端归档每页 8 条；搜索后重置到第 1 页。
- 搜索 / 分页写入 URL：`/posts?keyword=数据库&page=1`。
- 空结果展示“没有找到相关的文章”，不是请求失败。

### 5.4 文章详情：`GET /api/posts/{id}`

公开；只返回已发布文章，草稿 / 不存在都返回 **404**。

```json
{
  "code": 1,
  "message": "success",
  "data": {
    "id": 1,
    "title": "我的第一篇博客",
    "summary": "这是摘要",
    "coverUrl": null,
    "content": "# 你好\n\n这是第一篇的正文。",
    "publishedAt": "2026-10-20 10:00:00",
    "updatedAt": "2026-10-21 09:00:00",
    "viewCount": 13,
    "commentCount": 2
  }
}
```

- 每次成功读取，后端 `view_count + 1`；页面 meta 展示新值。
- `content` 是 **Markdown 原文**，前端负责渲染与 XSS 过滤。
- **实际后端 `commentCount` 目前固定为 0**（`PostDetail.of()` 写死），前端不依赖它：
  - 详情页的留言条数使用 `/comments` 返回的 `total`；
  - 404 时展示“这篇文章不在这片夜色里”。
- `commentCount` 类型保留在 `PostDetail` 类型里，等后端补齐。

### 5.5 评论列表：`GET /api/posts/{id}/comments`

公开；只返回 `status = 'approved'`，按 `createdAt DESC, id DESC`。

| 参数 | 位置 | 默认 | 约束 |
|---|---|---|---|
| `id` | path | — | 文章 id |
| `page` | query | 1 | ≥ 1 |
| `size` | query | 20 | 1～50 |

```json
{
  "code": 1,
  "message": "success",
  "data": {
    "list": [
      {
        "id": 8,
        "nickname": "小明",
        "website": "https://example.com",
        "content": "写得好",
        "createdAt": "2026-10-21 12:00:00"
      }
    ],
    "total": 1,
    "page": 1,
    "size": 10
  }
}
```

- 不返回 `email`、`ip`、`userAgent`。
- 前端详情页每页 10 条；总条数用于详情 meta 和分页。
- `content` 只做纯文本插值，**不使用 `v-html`**。
- `website` 只在通过 `safeHttpUrl()`（仅 http/https）后渲染为链接。

### 5.6 提交评论：`POST /api/comments`

公开；游客可提交。

```json
{
  "postId": 1,
  "nickname": "小明",
  "email": "ming@example.com",
  "website": "https://example.com",
  "content": "写得好"
}
```

| 字段 | 必填 | 约束 |
|---|---|---|
| `postId` | 是 | 必须存在且已发布 |
| `nickname` | 是 | 1～32 字符，去首尾空格 |
| `email` | 否 | 合法邮箱，≤128 |
| `website` | 否 | 以 `http://` / `https://` 开头，≤255 |
| `content` | 是 | 1～500 字符，纯文本 |

实际成功响应：

```json
{
  "code": 1,
  "message": "评论提交成功，请等待审核通过显示",
  "data": null
}
```

- 入库 `status = 'pending'`，记录 IP / User-Agent。
- **评论区不会立即出现新评论**；页面显示后端 `message`，并提示审核后显示。
- 前端做了：
  - 客户端校验（昵称 / 邮箱 / 网站 / 内容长度）；
  - 隐藏蜜罐字段，填入后静默丢弃；
  - 提交中禁用按钮；
  - 成功后 60 秒冷却（本地 UX，不是服务端安全边界）。
- 后端当前**没有实现** 5.6 文档中的 60 秒 / 每小时 10 条限流（`CommentServiceImpl` 里是 TODO）；前端 429 分支已准备好。
- 校验失败时后端目前返回 **Spring 默认错误 JSON**（没有统一 `message`、且带 `trace`），前端会用客户端校验拦截大多数情况，并把 400 统一显示为“提交内容不符合要求，请检查后重试”。

### 5.7 友链：`GET /api/friend-links`

公开；无分页，只返回 `visible = 1`，按 `sort_order` 升序：

```json
{
  "code": 1,
  "message": "success",
  "data": [
    {
      "id": 1,
      "name": "某某的博客",
      "url": "https://example.com",
      "avatarUrl": null,
      "description": "一个写代码的人"
    }
  ]
}
```

- 首页侧栏和 `/friends` 页都使用该结构。
- 首页来自 `/api/home` 的 `friendLinks`，友链页单独调用本接口。
- URL 不合法（非 http/https）时前端不渲染为可点击链接。
- 头像为空或加载失败时显示名称首字圆标。

### 5.8 认证：login / logout / me

#### 5.8.1 登录

```
POST /api/auth/login
Content-Type: application/json
```

```json
{ "username": "admin", "password": "你的密码" }
```

成功：

```json
{
  "code": 1,
  "message": "success",
  "data": { "id": 1, "username": "admin", "nickname": "站长" }
}
```

- 响应头 `Set-Cookie: JSESSIONID=...; HttpOnly; SameSite=Lax; Path=/`。
- 前端 `axios` 设置了 `withCredentials: true`，通过 Vite / Nginx 同源代理带上 Cookie。
- 错误：
  - 401：`message = 用户名或密码错误`，不区分用户名/密码。
  - 429 / 403：文档预留；**当前后端未实现**登录失败限流与账号禁用。
- 登录成功后前端保存 `data` 到 Pinia，并跳回 `?redirect=` 指定的站内路径（只允许以 `/` 开头的内部地址，拒绝 `//`）。

#### 5.8.2 当前用户

```
GET /api/auth/me
```

- 需要登录；未登录 401。
- 前端在 `App.vue` 挂载时调用一次，用于刷新页面后恢复登录态。
- 401 被当作“游客”，不弹错误；其他网络错误也按游客处理，不阻断公开页面。

#### 5.8.3 登出

```
POST /api/auth/logout
```

- 需要登录；服务端清空 SecurityContext 并销毁 Session。
- 成功响应 `{ code: 1, message: "success", data: null }`（与文档的“已退出登录”文案不同；前端使用自己的“已退出登录 / 退出成功”语义）。
- 401 表示会话已失效，前端清理本地 user；网络错误则保留登录态并提示重试，避免刷新后又“自动登录”。

### 5.9 联调发现的问题与前端处理

| 问题 | 实际情况 | 前端处理 |
|---|---|---|
| 首页评论字段拼写 | 文档 `latestComments`，后端实际 `lastestComments` | 两种 key 都接受，见 `src/api/home.ts` |
| 首页 `viewCount` | 文档示例没写，实际 `PostListItem` 会返回 | 类型设为可选；0 不显示“0 次阅读” |
| 详情 `commentCount` | 后端固定返回 0 | 用评论接口 `total` 展示真实条数 |
| 评论成功文案 | 后端 `message = 评论提交成功，请等待审核通过显示` | `post()` 保留 message 并展示 |
| 参数校验错误 | Spring 默认错误 JSON，没有统一 `Result`，带 `trace` | 客户端先校验；400 显示统一友好文案 |
| 评论限流 | 文档写了 429，后端 TODO 未实现 | 前端 60 秒冷却 + 蜜罐；429 分支可用 |
| 登录限流 | 文档写了 429 / 403，后端未实现 | 只处理 401；429 通用文案已准备 |
| 路径评论 id | 实际 `/api/posts/1/comments` 可正确返回 2 条 | 按文档调用，无额外 query |

> 建议后端后续统一：`lastestComments → latestComments`、补 `PostDetail.commentCount`、补 `MethodArgumentNotValidException` 统一错误体、实现评论/登录限流。

## 6. 数据流与状态

### 6.1 首页

```text
HomeView
  └─ useHome() → GET /api/home
       ├─ latestPosts → 主推 + 网格 / 单篇宽卡
       ├─ lastestComments → 侧栏留言
       └─ friendLinks → 侧栏友链
```

加载骨架、错误重试、空数据；首页内容只发一个 `/api/home` 聚合请求。  
App 启动时另发一次 `/api/auth/me` 恢复登录态；游客收到 401 是正常路径，不显示错误。

### 6.2 归档页

- URL 是唯一状态源：`?page=&keyword=`。
- `watch([page, keyword])` 触发请求；`requestId` 防止旧请求覆盖新结果。
- 搜索提交 → `router.push` 重置 page=1；清空 → 回到 `/posts`。
- 分页 → `router.push` 更新 page；浏览器前进/后退可还原。
- 空结果和请求失败分开处理。

### 6.3 详情页

- 文章和评论**并行请求**：
  - `GET /api/posts/{id}`；
  - `GET /api/posts/{id}/comments?page=1&size=10`。
- 文章 404 → 详情专属 404 状态；评论失败只影响评论区，不影响正文。
- 评论翻页只重新请求评论，不重复增加文章浏览量。
- 成功后 `document.title = 标题 · Start Night`。
- 评论提交成功后不乐观插入（因为 pending），只显示审核提示。

### 6.4 登录态

`src/stores/auth.ts`：

```text
user: UserInfo | null
loading: boolean
restored: boolean
error: string
```

- `restore()`：App 挂载时调用 `/auth/me`；401/网络错误 → 游客。
- `login()`：POST `/auth/login`，保存用户，清空错误。
- `logout()`：POST `/auth/logout`；401 → 本地清理；其他错误保留用户并提示。
- 没有 localStorage 存 token；登录态完全依赖 HttpOnly Session Cookie，前端读不到，降低 XSS 窃取风险。

### 6.5 Header 账号菜单

- 未登录：点击“登录” → `/login?redirect=当前路径`。
- 已登录：显示昵称首字 + 昵称 → 浮层显示 `@username` + 退出登录。
- 外部点击 / Esc / 路由变化自动关闭。
- 退出失败时浮层内显示错误，不静默清空。

## 9. 构建与部署

生产建议同域部署：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/start-night/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /uploads/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
    }
}
```

要点：

- `try_files ... /index.html` 支持 `/posts/1` 这类 SPA 路由刷新。
- `proxy_pass` 不要加尾部 `/`，避免 `/api/home` 被重写。
- Session / 评论 / 登录都依赖 Cookie；同域最省心。
- 生产 `VITE_API_BASE_URL=/api`，`VITE_ASSET_BASE_URL` 留空。

## 10. 可访问性、SEO 与性能

### 10.1 可访问性

### 10.2 SEO

- `index.html` 有 title、description、OG。
- 路由 afterEach 更新 title；详情加载后覆盖为文章标题。
- 当前 SPA 对搜索引擎的动态抓取有限；后续可预渲染文章详情 / 归档。
- Markdown 内容不在首屏 HTML 中，不做误导性静态描述。

### 10.3 性能

构建实测（Vite 7.3.7）：

- 首屏：`index` JS gzip ≈ 63.8KB + `HomeView` ≈ 5.2KB；CSS ≈ 3.3 + 3.2KB。

- 首页内容 1 个聚合请求 + 1 次 `/api/auth/me` 会话检查（游客 401 正常）。
- 首页角色图 eager + high priority；列表封面 lazy。
- 图片容器先占比例（16:10 / 16:9），降低 CLS。
- 无 UI 库、无外部字体、无动画库。
- Markdown 解析只在详情页加载。

## 12. 已知限制与下一步

### 12.1 当前限制

1. **没有后台管理页面**：九个接口只有认证，没有 admin CRUD；登录目前只保持站长会话，不能发文章 / 审评论 / 管友链。
2. **评论 / 登录限流未实现**：前端 60 秒冷却和蜜罐只是 UX，不是安全边界；后端 TODO。
3. **参数校验错误体不统一**：Spring 默认 JSON 没有统一 `message`，且带 `trace`；前端用客户端校验和通用 400 文案兜底。
4. **详情 `commentCount` 固定 0**：前端改用评论接口 `total`。
5. **首页评论字段拼写**：`lastestComments`；前端兼容，建议后端改名。
6. **文章封面为空**：当前 `coverUrl` 为 null，显示夜空占位；上传后自动显示。
7. **搜索只按标题**：`keyword` 不搜正文 / 标签；没有分类 / 标签字段。
8. **Markdown 无语法高亮 / 目录 / 标题锚点**：代码块只有统一深色样式。
9. **SPA SEO 限制**：详情动态内容不在初始 HTML；后续可预渲染。
10. **当前数据量小**：分页 / 评论翻页的实际多页状态需要更多数据验证。

### 12.2 下一步

- **P1 后台管理**（需要后端 admin 接口）：
  - 登录守卫 + 后台布局；
  - 文章 CRUD / Markdown 编辑器 / 封面上传；
  - 评论审核；
  - 友链管理。
  - 此时再引入 Element Plus 和完整后台权限。
- **P2 评论体验**：评论回复、通知、表情、审核状态查询。
- **P3 内容发现**：归档年份、标签 / 分类（需后端加表）、相关文章。
- **P4 Markdown 增强**：Shiki 高亮、TOC、标题锚点、图片灯箱。
- **P5 部署与 SEO**：预渲染、RSS、sitemap、站点地图。
- **后端修复建议**：
  1. `Home.lastestComments` → `latestComments`，同步文档；
  2. `PostDetail.commentCount` 查询真实已通过评论数；
  3. `MethodArgumentNotValidException` 统一成 `Result`，去掉 trace；
  4. 评论 60s / IP 每小时限流；
  5. 登录失败限流 / 账号禁用字段。
